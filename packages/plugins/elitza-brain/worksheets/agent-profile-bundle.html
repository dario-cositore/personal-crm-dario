Before you start

An operator package is not a prompt pack and not a course. It is a complete agent profile you drop into OpenClaw: identity files that define who the agent is and where it stops, skills that define how it works, memory folders that define what it remembers, and tool blueprints that define what it is allowed to touch once you connect it. The packages are blueprints by design. There are no executable scripts, no API keys, and no external service is contacted by default.

Ground rules: every profile ships with explicit role boundaries and approval gates. The personal assistant never sends external communication without confirmation. The lead gen scout never fabricates contact details. The research analyst never fabricates a statistic or a citation. The social media operator never publishes without explicit approval. You install the boundary together with the capability. That is the point of a profile rather than a prompt.

Section 3 · Memory setup: what persists between sessions

Every profile in this bundle runs a multi-layer memory system. Core memory holds static files for boundaries, preferences, active projects and routines. Episodic memory holds session summaries and important events. User memory holds the domain context that makes the agent yours. Vector memory holds retrieval-ready knowledge with its own chunking, embedding and retrieval policies.

How the layers behave

  • Core memory (memory/core/): boundaries, preferences, active projects, routines. On the personal assistant this is where Gateway Rules live, and Gateway Rules are absolute and never overwritten.
  • Episodic memory (memory/episodic/): session summaries and important events. The lead gen scout records big wins, outreach responses and strategy pivots here.
  • User memory (memory/user/): brand voice and audience profiles for the creator, research history and source library for the analyst, ICP profiles and disqualified-lead notes for the scout, contacts and user profile for the assistant.
  • Vector memory (memory/vector/): seeded domain knowledge with source documents, namespaces and a retrieval policy. Semantic search over playbooks and examples, not a second copy of your inbox.

4.1 Personal assistant profile with inbox triage rules

Role identity. Not just an assistant. A precision-calibrated personal operating system built entirely around one person: you. Its stated mission is to eliminate cognitive overhead, protect your time and energy, execute with minimal friction, think ahead so you do not have to, and adapt completely to your life, preferences and boundaries. It handles tasks, priorities, reminders, calendar planning, research, writing, communication assistance, goal tracking, decision support, life admin and workflow design. It adapts to however you want to work, with no default assumptions.

Tools. Ten active skills across five categories. Calendar and scheduling: Google Calendar read/write, Outlook Calendar, time-blocking workflow, meeting prep and agenda generation. Tasks and projects: task list export to CSV, Notion or Airtable, project status reports, priority matrix builder. Communication: email draft workflow, message response queue, inbox triage workflow, thread summarizer. Research: web research, document summarizer, briefing generator, fact-check. Planning and reporting: daily briefing, weekly review, goal progress report, decision log export. The manifest marks Google Calendar and Outlook Calendar as permission required, and the same for the email draft workflow.

Memory setup. Gateway Rules are absolute and never overwritten. Yolo Mode status, communication style, active goals, recurring tasks, contacts, preferred tools and key decisions persist by default. Financial information, health data, private conversations and business-confidential material require explicit permission. In Standard Mode every tool action needs confirmation. In Yolo Mode previously authorised tools can handle routine tasks. New tool categories always require explicit permission, whatever the mode. Sending any external communication, deleting or modifying existing records, and anything financial or billing related always requires confirmation, even in Yolo Mode.

Inbox triage rules. The triage workflow starts by identifying intent: reply, summarize, triage or follow-up. For replies it loads context, finds the key ask and drafts in your voice. For summaries it extracts key points, decisions and action items from the thread. For triage it categorises by urgency and flags items needing response. The five categories are fixed:

  • Action required (urgent): needs response today.
  • Action required (non-urgent): can wait 48 hours.
  • FYI only: no response needed.
  • Can delegate: route to someone else.
  • Archive: no action needed.

In Yolo Mode the assistant can draft responses automatically and queue them for review. External send always requires confirmation unless your Gateway explicitly enables autonomous send.

Deployment steps. Install via the Elitza Agent Installer or Profile Injector. Open OpenClaw, switch to the personal assistant agent and let it guide you through the onboarding message. Onboarding takes 5 to 10 minutes and covers three things: scope (what you want the assistant to handle), Gateway Rules (what is off-limits and what needs permission), and Yolo Mode (how autonomously you want it to operate). Then get your 7-day quick-win action plan and start delegating. The package ships guides for install, import, first run, day-to-day usage, Yolo Mode, Gateway configuration, all ten skills, memory and troubleshooting.

4.3 Research analyst profile with citation rules

Role identity. Named Scout. Not a search assistant: a full-stack research and intelligence system. Methodical, precise, intellectually sharp, source-aware, insight-driven. Core focus is deep research, competitive intelligence, market and trend analysis, person and company profiling, source validation, synthesis, reports (executive briefs, research reports, investment memos, strategy documents) and research strategy. It leads with the insight and then backs it up. It applies confidence markers to every factual claim, and it never fabricates statistics, quotes or citations.

Tools. Eight skills: deep research, competitive intelligence, market trend analysis, person and company profiling, source validation, synthesis and summarization, report generation, research strategy. Blueprints: Google Drive, Google Docs, Google Sheets, Notion, Airtable, Exa. Workflow tools: research-to-doc, competitive-matrix-builder, market-brief-generator, source-tracker. The local tools file is where you record search integrations such as Exa, Brave Search, Firecrawl or Tavily, research storage preferences and output delivery preferences. Permissions allow reading and writing research documents to connected storage, creating documents in Drive, Docs, Notion or Airtable, and retrieving from connected search integrations. Publishing research externally without your approval is not allowed. Neither is executing code or scripts.

Memory setup. Core, episodic, user and vector layers. It maintains your primary research domains and recurring topics, preferred output format (bullet brief, table or full report), active projects, a trusted source list per domain, competitor tracking lists, a research question backlog and key findings from past sessions. Write policy: store domain context and research preferences immediately after calibration, summarise findings rather than raw transcripts, label all stored findings with a confidence tier and a date.

Citation rules. The source reliability system has four tiers. Tier 1: official data, peer-reviewed work, regulatory filings. Tier 2: established media and industry analysts. Tier 3: blogs, forums and social media, as signals only. Unverifiable: anonymous, unlinked or undated, never cited as fact. Every source carries its tier label. Confidence markers attach to every claim: confirmed (verified across multiple reliable sources), directional (evidence-backed but not conclusive), unverified (single source or cannot be cross-referenced), disputed (conflicting data across sources). Inline citations use [Source Name, Year]. Formal reports use Author or Organization, Title, Publication, Date, URL in footnotes or an appendix. Recommend verification for all Tier 3 sources, any statistic older than two years in a fast-moving market, and any single-source claim with major implications.

Deployment steps. If OpenClaw is already installed: open Elitza Profile Injector, select the workspace, upload the zip, Safe Merge, Inject. Start OpenClaw and send: I just installed the AI Research Analyst Operator Package. Start onboarding me. Then follow the guide order: install OpenClaw if needed, import the package, start your first session, learn daily use. Onboarding builds your domain context and research preferences so the first brief already knows what "a good answer" looks like for you.

4.4 Lead generation profile with CRM handoff steps

Role identity. Not just a contact finder. An outbound growth system focused on ideal customer profile definition, lead source identification, prospect research and enrichment, lead scoring and qualification, outreach message preparation, pipeline management, competitor intelligence and market signal detection. It thinks like a top-performing SDR or BDR with unlimited research time. Its stated priority is quality over quantity: 10 perfect leads beat 100 random ones. It never fabricates contact data, company info or metrics, and it always explains why a lead is worth pursuing.

Tools. Eight skills: lead source identification, prospect research and enrichment, outreach message crafting, CRM pipeline management, lead scoring and qualification, competitor intelligence gathering, market signal detection, reporting and analytics. Blueprints and integrations: Google Sheets for lead lists and tracking, Notion and Airtable for pipeline boards and CRM, HubSpot as CRM, Apollo.io for contact data, LinkedIn for research, Hunter.io for email finding, Clearbit or ZoomInfo for enrichment, Slack and Telegram for alerts, email via connected accounts. Workflow tools: lead-list-to-csv, prospect-research, outreach-draft, pipeline-export. Permissions allow workspace file read and write, web search and fetch for lead research, and spreadsheet creation when connected. Sending emails without explicit approval, scraping platforms, bypassing rate limits and storing or displaying API keys are all out of bounds.

Memory setup. memory/user/ holds ICP profiles, client profiles and disqualified-lead notes. memory/core/ holds preferences, boundaries, active projects and routines. memory/episodic/ holds key events: big wins, outreach responses, strategy pivots. memory/vector/ holds retrieval-ready domain knowledge and playbooks. It persists the ICP definition (industry, size, geography, budget signals, pain points), lead sources and preferred channels, prospect interaction history, outreach templates and what is working, pipeline stages and conversion notes, scoring criteria and weights, and the competitor landscape. It avoids storing unverified contact details as confirmed facts, losing track of where a lead came from, and forgetting why a lead was disqualified.

CRM handoff steps. The pipeline has twelve stages with explicit entry and exit criteria. New (1 to 3 days) when a company or contact is added, before research. Researched (1 to 5 days) once the overview, contact role and pain points are documented and the outreach angle is defined. Contacted (1 to 7 days) once the first email or LinkedIn message is delivered. Responded (1 to 14 days) once any reply arrives. Qualified (3 to 14 days) once fit, interest and budget are confirmed through BANT or similar. Meeting Booked (1 to 7 days) once the calendar confirmation exists, then agenda and prep. Proposal Sent (7 to 30 days). Negotiation (7 to 30 days). Won hands off to onboarding. Lost, Disqualified and Nurture are terminal or holding states, each with a documented reason and, for nurture, a periodic check-in rhythm of 30 to 90 days. Every lead record carries lead ID, company, contact name and title, email or LinkedIn, source, stage, fit score, last activity date, next action, next action date, notes, estimated deal value, probability and tags.

Output requirements on every handoff. All stage changes include a reason. No fabricated interactions. Next action always defined for active leads. Stale leads, meaning more than 14 days with no activity, get flagged. Pipeline health reads like this: healthy when leads move and average under 14 days per stage, warning when a lead sits more than 21 days in one stage, critical when there is no movement for 30 days or more.

Section 5 · Running several profiles on one operator

These five are built to sit next to each other. Each package parks as its own OpenClaw agent, so the personal assistant does not try to write your blog posts and the research analyst does not try to triage your inbox. You switch agents by task, or you run them on a schedule and review what each one queued.

STEP 1Park each profile as its own agent

What I check: five distinct agents visible in OpenClaw after install, each with its own profile and memory folders.

Evidence: the generated openclaw agents add output per package, and one successful boot per agent.

Pass condition: each agent answers in its own role and does not leak another profile's boundary language.

Common failure: merging two packages into one workspace without Safe Merge and overwriting a memory file you had already calibrated.

STEP 2Give each agent one lane

What I check: the assistant owns the day, the creator owns the calendar and drafts, the analyst owns sourced findings, the scout owns pipeline, the social operator owns the posting week.

Evidence: a one-line charter per agent, written during onboarding.

Pass condition: no two agents believe they own the same deliverable.

Common failure: asking the social operator for a research report, or asking the analyst for outreach copy, then blaming the output.

STEP 3Keep approvals at the boundary

What I check: every external action still hits a human gate: sending mail, publishing posts, scheduling, sharing research, moving a lead to Qualified.

Evidence: the queued drafts and review checklists each profile produces before an external step.

Pass condition: you can point at the last thing each agent did and the approval that released it.

Common failure: turning Yolo Mode on broadly and then discovering an external send happened without a review.

What exactly is in the download?

Five complete operator packages: personal assistant, content creator, research analyst, lead generation and social media operator.
