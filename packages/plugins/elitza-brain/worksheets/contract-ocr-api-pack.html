This pack is the extraction layer I put in front of any document pipeline that has to produce structured records instead of a pile of text. The vision model reads the page in context. The schema decides what is allowed to leave. The validator decides what is allowed to write. You get the prompt, the schemas, the thresholds, the retry wording and the Python call that runs all of it.

Before you start

Template based OCR treats a page as a fixed coordinate map. Field at x, y. Label at x2, y2. It works on one clean scan and falls apart on everything else: a retainer with a new letterhead, a lease with an addendum stapled on, a court filing where the caption moved down a line, an ID photo taken at an angle. A vision-language model reads the page the way a person does. Layout, tables, handwriting, shifted blocks. The schema is what keeps that read honest.

Ground rules: never let the model write directly into a system of record. Extraction produces a candidate payload. Validation decides if the payload is safe. Confidence decides if a human sees it. Only then does anything write. Keep the original document beside every extracted object so any field can be traced back to a page.

Section 2 · The extraction prompt and its output rules

One prompt template, parameterised by document type and target schema. The rules are hard on purpose. A prompt that allows prose allows silent parse failures downstream.

Extraction prompt template

ROLE
You extract structured fields from legal documents. You never
summarize, never infer, never invent.

INPUT
document_type: {{engagement | nda | service_agreement | lease |
                court_filing | identity | contract}}
matter_hint: {{case_type if known}}
target_schema: {{schema_name}}
page_count_hint: {{expected pages, or null}}

RULES
1. Return JSON only. No prose before or after.
2. Wrap output exactly as:
   <response><json>{...}</json></response>
3. Read numbers as they appear in the document. Spell-out
   numbers convert to digits: "thirty-six thousand six hundred
   five" becomes 36605. If the digits and the words disagree,
   set numeric_conflict: true and use neither value.
4. Dates become YYYY-MM-DD. If only a partial date exists,
   set date_precision to year, month or day.
5. Jurisdiction is the stated one. If absent or ambiguous,
   return null. Do not guess from the party names.
6. Every field in the required list must be present. Use null
   for genuinely absent values, never an empty string.
7. Quote source text for each extracted value under
   "evidence". If you cannot locate the source text, the
   field is null.
8. Party fields capture the full legal name as written.
   Roles are separate fields. Do not merge a company and its
   signatory into one string.
9. Currency is ISO 4217. If the document states a symbol with
   no currency code, infer the code only when the symbol is
   unambiguous for the stated jurisdiction. Otherwise
   currency: null and amount: null.
10. Never average, round or normalise a figure the document
    states. Transcribe, then let code normalise.
11. If two sections disagree on the same fact, keep both under
    "conflicts" and set the primary field to null.
12. If the document is unreadable, return
    {"status":"unreadable","reason":"..."}.

OUTPUT
JSON object conforming to the target schema.

What each rule prevents

RuleFailure it stopsWhere it bites if you drop it
1 JSON onlyMarkdown fences and commentary around the objectEvery downstream parse step
2 response / json wrapperModel talking past a strict extractorRetry logic, logging, schema registry
3 digit vs word numbersInvented numeric conversionsFees, deposits, penalties, damages
4 date precisionFalse day-level confidence on a month-only dateNotice windows, limitation periods
5 jurisdiction as statedGuessed governing law from a party addressVenue, conflict checks, court routing
6 null not empty stringEmpty writes that look like real valuesCRM required fields, search indexes

Retry wording (use this, not a longer prompt)

When the first pass fails envelope parse or schema validation, retry once with a reduced prompt. Do not argue with the model. Narrow the job.

RETRY
The previous response did not validate against the target
schema. Return JSON only, wrapped as
<response><json>{...}</json></response>.

Extract ONLY these fields:
{{comma separated required field list}}

If a field is not on the page, return null.
If two sections disagree, set the field to null and list the
quotations under "conflicts".
Do not explain. Do not add fields.

Two attempts is the ceiling. A third attempt is superstition. After two failures the document goes to the reviewer queue with both raw responses attached.

Section 3 · Schemas that reject anything the model invents

One base envelope, six type-specific property sets. The envelope carries status, confidence, evidence and conflict state. The property sets carry the fields that actually differ by document. Validate the envelope first, then the property set for the type you requested. Anything not in the schema is dropped before it reaches a record.

Base envelope schema

Section 4 · Validation: numbers, dates, cross references

Validation runs in code, not in the prompt. The prompt asks for honesty. The validator enforces it. Run every check below on every payload before anything writes.

Validation rules

Envelope check: the <response><json> wrapper parses, then the inner object parses as JSON. Reject and retry with the reduced prompt if not.
Type check: every field matches its declared type. Integer fields reject floats. Number fields reject strings with currency symbols still attached.
Required check: every field in the type's required list is present. Null is allowed only where the schema allows it. A required field that is null forces escalation.
Range check: amounts non-negative, notice days between 0 and your ceiling, confidence between 0 and 1, expiry dates in the past on identity documents.
Enum check: fee type, lease type, filing type, urgency and jurisdiction limited to values your CRM actually accepts. Anything else is a mapping failure, not a new value.
Numeric consistency: if digits and words disagree, or the same figure appears twice with different values, set numeric_conflict and stop. Language models hallucinate numeric conversions. This is the most expensive class of error in a legal document.
Date shape and order: values match their date_precision. End date after start date. Expiry after issue. Hearing date not before filing date. Notice windows consistent with the termination clause.
Cross-reference parties: party names appear in the evidence map. Each party name is checked against your conflict list and existing contact records before any write.
Evidence present: each required field has a source quote and a page. A field with no evidence is treated as absent.
Unknown key check: any property outside the schema is dropped and logged. The model does not get to invent fields.

Python: vision call, schema validation, routing

One module. Call the model with the document and the prompt. Parse the envelope. Validate against the base schema and the type property set. Run the cross-checks. Route on the result. This is the shape I ship.

import base64, json, re
import anthropic
from jsonschema import Draft7Validator

client = anthropic.Anthropic()
ENVELOPE = json.load(open("schemas/ocr/envelope.v1.json"))
SETS = json.load(open("schemas/ocr/property_sets.v1.json"))
FLOORS = {"engagement": 0.88, "nda": 0.86, "service_agreement": 0.86,
          "lease": 0.87, "court_filing": 0.85, "identity": 0.92,
          "contract": 0.85}
WRAPPER = re.compile(r"<response><json>(.*)</json></response>", re.S)
JURISDICTION_REQUIRED = {"engagement", "nda", "service_agreement",
                         "lease", "court_filing", "contract"}


def doc_block(path):
    data = open(path, "rb").read()
    b64 = base64.b64encode(data).decode()
    if path.endswith(".pdf"):
        return {"type": "document",
                "source": {"type": "base64",
                           "media_type": "application/pdf", "data": b64}}
    return {"type": "image",
            "source": {"type": "base64", "media_type": "image/png",
                       "data": b64}}


def parse_envelope(text):
    m = WRAPPER.search(text or "")
    if not m:
        raise ValueError("envelope_missing")
    return json.loads(m.group(1))


def validate_payload(payload, doc_type):
    errs = [f"envelope:{e.message}"
            for e in Draft7Validator(ENVELOPE).iter_errors(payload)]
    fields = payload.get("fields") or {}
    props = SETS[doc_type]["fields"]
    wrapped = {"type": "object", "properties": props,
               "additionalProperties": False}
    errs += [f"fields:{e.message}"
             for e in Draft7Validator(wrapped).iter_errors(fields)]
    for name in SETS[doc_type]["required_fields"]:
        if name not in fields:
            errs.append(f"missing_required:{name}")
        elif fields.get(name) is None and name != "jurisdiction":
            errs.append(f"null_required:{name}")
    return errs


def cross_checks(payload):
    errs = []
    fields = payload.get("fields") or {}
    if payload.get("numeric_conflict"):
        errs.append("numeric_conflict")
    pairs = [("effective_date", "end_date"), ("effective_date", "expiration_date"),
             ("start_date", "end_date"), ("commencement_date", "expiration_date"),
             ("issue_date", "expiry_date"), ("filing_date", "hearing_date")]
    for a, b in pairs:
        if fields.get(a) and fields.get(b) and str(fields[b]) <= str(fields[a]):
            errs.append(f"date_order:{a}>={b}")
    for name, cell in (payload.get("evidence") or {}).items():
        if not cell.get("quote") or not cell.get("page"):
            errs.append(f"evidence_incomplete:{name}")
    dt = payload.get("document_type")
    if dt in JURISDICTION_REQUIRED and not payload.get("jurisdiction"):
        errs.append("jurisdiction_missing")
    return errs


def retry_prompt(doc_type):
    required = ", ".join(SETS[doc_type]["required_fields"])
    return ("RETRY\nReturn JSON only, wrapped as "
            "<response><json>{...}</json></response>.\n"
            f"Extract ONLY these fields: {required}\n"
            "If a field is not on the page, return null. "
            "Do not explain. Do not add fields.")


def extract(path, doc_type, schema_name):
    system = "You extract structured fields from legal documents."
    base_prompt = open("prompts/extraction.v1.txt").read().format(
        document_type=doc_type, matter_hint="null",
        target_schema=schema_name, page_count_hint="null")
    prompt, raw = base_prompt, ""
    for attempt in (1, 2):
        msg = client.messages.create(
            model="claude-sonnet-4-5", max_tokens=4096, system=system,
            messages=[{"role": "user", "content": [
                doc_block(path), {"type": "text", "text": prompt}]}])
        raw = msg.content[0].text
        try:
            payload = parse_envelope(raw)
        except (ValueError, json.JSONDecodeError):
            prompt = retry_prompt(doc_type)
            continue
        errs = validate_payload(payload, doc_type) + cross_checks(payload)
        floor = FLOORS[doc_type]
        ok = (payload.get("confidence", 0) >= floor
              and not errs and not payload.get("numeric_conflict"))
        payload["meets_threshold"] = ok
        if ok:
            return {"result": "accepted", "payload": payload,
                    "attempt": attempt}
        prompt = retry_prompt(doc_type)
    reason = "two_failed_attempts" if errs else "below_confidence_floor"
    return {"result": "escalate", "payload": payload, "errors": errs,
            "raw_responses": [raw], "reason": reason}
Do not skip the validator because the model looked right. A payload can be fluent, complete and wrong on the fee. The validator is the only layer that does not care how convincing the JSON is.

Section 5 · Escalating to a human when confidence drops

Reviewer checklist

Open the source page beside the candidate payload. Not the summary. The page.
Confirm every required field against the evidence quote before changing anything.
Correct by writing a corrected object. Never overwrite the model output. Both versions stay.
Record why the model was wrong: layout, illegible, ambiguous clause, bad page split.
If the same reason appears three times in a week, change the prompt or the schema. Do not keep correcting by hand.
Close the item with a decision: accept as corrected, reject and re-request, or block for attorney sign-off.
Queue rules: one role per document type. SLA on every open item, escalating when it ages. Rejection is a valid outcome and routes to a named person, not back into the loop. Corrections append. Bulk close is disabled.

Section 6 · FAQ

Does this replace my current OCR tool?

It replaces the extraction and validation layer. If a tool already stores and versions documents, keep it. Point the tool at this call instead of its built-in template mapper.

Which model does the Python call use?

A vision-capable model API with zero data retention configured on your account. The sample uses an Anthropic messages call with a document block. Swap the client, keep the schema and the validator.

Why not just ask the model harder?

Because a prompt cannot enforce a type. It can only request one. The schema rejects invented keys, the validator rejects bad values, and the queue catches the rest. Three layers, each one mechanical.

What about handwritten signatures and stamps?

Treat them as evidence of execution, not as fields. Capture presence, date if legible, and the page. Do not ask the model to invent a signatory name from a flourish.

Can I add a seventh document type?

Yes. Copy a property set, list the required fields, pick a confidence floor from the closest neighbour, and version the schema. Table 3A is the worksheet for it.
